# 3D — 설명하는 3D와 인터랙션

기준이 되는 발표는 **숨길**(ESG 강의 팀 과제, 2026-11)이다. 표지와 01장의 흰 도식 도시 위로 두 경로가 그려지고, 숨김 장에서는 아이오닉 6을 열어 E-GMP 내부를 보였다. 그 수준을 다른 주제에서 혼자 다시 만들 수 있게 판단과 도구를 모은 것이 이 문서다. 실제 코드는 [examples/sumgil/](../examples/sumgil/README.md)에 있다.

**3D는 장식이 아니다.** 평면으로 그리면 놓치는 관계가 있을 때만 쓴다. 쓰더라도 `design.md`의 체계(흰 바탕, 강조색 하나, 상자 없음, 24px 이상)를 그대로 지킨다. 3D 장면은 그 체계 위에 "떠 있는" 그림이다.

## 1. 3D를 쓸까 (장마다 판단)
`viz.md` 설계 절차의 3단계("관계를 시각 변수로")에서, 아래 중 하나일 때만 3D 후보로 올린다.

| 보여야 할 관계 | 3D가 하는 일 | 형태 | 숨길에서 |
|---|---|---|---|
| **어디서·어떤 경로로** (공간·이동) | 같은 장소 위에서 두 선택을 겹쳐 본다 | 도식 장면(diagram): 흰 도시·지형 + 그려지는 경로 | 01장 지도, 표지 반복 |
| **무엇으로 이뤄졌나** (실물의 구조) | 겉 → 속 → 부품을 한 물체에서 차례로 연다 | 에셋 소개(inspect): 실물 모델 분해·투시·초점 | 숨김 장 전기차 해부 |
| **세계관·첫인상** (표지·마무리) | 이야기의 무대를 한 장면으로 각인 | 도식 장면 반복 모드(loop) | 표지 도시, 마무리 수미상관 |

이럴 때는 3D를 쓰지 않는다: 크기 비교(막대가 정확), 시간 변화(선), 비율(누적 막대), 과정(흐름) — 3D 차트·3D 파이·회전하는 로고는 금지(`design.md`). 정하기 어려우면 같은 장을 2D 안과 3D 안으로 만들어 캡처를 보여 주고 묻는다(질문 S1, [3d-taste.md](3d-taste.md) 끝).

## 2. 두 가지 형태와 도구

### 도식 장면 (look `diagram`) — 지도·경로·도시·흐름
- **스크립트로 빛을 정점 색에 굽고 → three.js는 구운 색 그대로(unlit).** 웹에서 계산할 빛이 없어 가볍다. 대체 PNG도 같은 메시를 같은 카메라로 찍으므로 3D 화면과 똑같다.
- 도구: `deck.mjs build3d <장면.mjs>`(헤드리스 Chrome + three.js, Blender 없음), `scripts/3d/kit3d.js`(토큰 색·근거 값 읽기, 형상, 이분법, 카메라 맞춤, 빛 굽기, GLB·PNG·JSON 쓰기), 출발점 `scripts/3d/route-city.mjs`.
- 런타임: `web/js/viz/stage3d.js`(무대·단계·트윈·라벨·대체 그림·셰이더 조각). 출발점 모듈 `examples/gallery` 의 `custom/route3d.js`.
- 자세히: [3d-build.md](3d-build.md) "도식 장면", [3d-runtime.md](3d-runtime.md).

### 에셋 소개 (look `product`) — 제품·기기·차량·설비·구조물
- **고품질 오픈소스 모델을 최대한**: 찾아서 그대로 → 다듬어서 → 3곳 이상 뒤져도 없을 때만 공개 제원으로 직접 만든다(어림 형상, `searched` 기록). 부품마다 노드 하나, `extras {part, group}`.
- 런타임: `web/js/viz/inspect3d.js` — 설정 JSON만으로 외관 → 투시 → 분해 → 부품 초점(카드 숫자는 근거 id) → 조립, 드래그로 둘러보기. 숨김 장 해부를 그대로 재현한다.
- 출발점: `scripts/3d/power-bank.mjs`(직접 만든 조립품 → GLB + 같은 빛·구도의 포스터), 갤러리 `asset3d` 장.
- **조사가 반이다**: 무엇을 보일지 → 제원 근거 → 모델 찾기·라이선스 → 다듬기 → 빈 부품 직접 만들기 → 맞춤 검사. [3d-asset-research.md](3d-asset-research.md)를 처음부터 따른다.

## 3. 어디서나 지키는 것 (숨길에서 사용자가 고친 지점에서 나옴)
1. **비율은 정직하게.** 도식이라도 근거가 있는 양(경로 길이, 크기 차이)은 근거 비율대로 그린다. 장면 스크립트가 이분법으로 형상을 맞추고(`dk.bisect`), 런타임이 다시 확인한다(`checkRatio` → 어긋나면 console.error = 검수 ERROR). 화면 하단에 "지도 도식 · 실제 경로 형상 아님", "내부 구조는 어림 형상"처럼 무엇이 실제가 아닌지 쓴다.
2. **숫자는 근거 장부에서만.** 라벨 km, 카드 큰 숫자, 보조 줄 숫자 모두 `num(id)` · `"num": "id"` · `"{id}"`. 코드·설정에 숫자 글자를 쓰지 않는다(숨김 장 첫 판은 이걸 어겨 다시 고쳤다).
3. **글자는 굽지 않는다.** 라벨은 HTML/SVG 층에 토큰 색으로, 3D 점을 화면에 투영해 놓는다(`st.project`). 라벨 4개 이하, ● 6px + 1.5px 리더선, 흰 외곽선.
4. **틀이 없다.** 도식 장면은 투명 캔버스 + 가장자리가 바탕색으로 사라짐(`edgeFade`, PNG는 같은 식의 `dk.fadeCanvas`). 실물은 흰 스튜디오 + 바닥 그림자 판. 상자·베젤·그림자 테두리 없음.
5. **움직임은 설명할 때만, 물 흐르듯.** 단계마다 정해 둔 자세로 1.0초 ease-in-out, 경로는 같은 속도(길이 비율만큼 시간), 차 주행 같은 출발·정지(`ease.drive`). 사라지고 나타나는 대신 이어서 변한다. 설명 장에 자동 회전·카메라 흔들기 없음(탐색 장의 유휴 회전만 예외). → [3d-taste.md](3d-taste.md)
6. **장에 들어올 때는 애니메이션 없이 그 단계 모습으로.** 앞으로 갈 때만 움직이고, 뒤로 가면 짧게 되돌린다. `prefers-reduced-motion`이면 늘 바로 놓는다(`watchSlide`가 처리).
7. **언제나 대체 그림.** `?no3d`, WebGL 없음, 불러오기 실패, 컨텍스트 손실 → 같은 카메라의 PNG(도식) 또는 포스터(실물) + 같은 자리 라벨. 의도하지 않은 실패는 console.error.
8. **움직일 때만 그린다.** 장이 present일 때만, 트윈이 살아 있을 때만 프레임. 해상도 = 보이는 크기 × 기기 배율(상한 1.5~1.6), 느리면 스스로 낮춤. 셰이더 예열로 첫 전환 멈칫 제거. 숨겼다 다시 보이는 대신 흐리게(GPU 재업로드로 멈칫).

## 4. 만드는 순서 (장 하나)
1. 장 기획(`slides/<slug>.md`)에 3D를 쓰는 이유 한 줄: "평면이면 놓치는 관계 = …". 형태(diagram / inspect), 단계별로 무엇이 바뀌는지 표(카메라·그려지는 것·라벨).
2. 에셋: 도식이면 장면 스크립트를 출발점에서 복사(`deck/tools/3d/<slug>.mjs`)해 장면을 바꾸고 `deck.mjs build3d deck/tools/3d/<slug>.mjs -- …`로 GLB·PNG·JSON을 만든다(몇 초). 장면의 소품(차·사람·나무·건물)·질감·환경광은 CC0 묶음(Kenney·Quaternius·Poly Pizza·Poly Haven)에서 먼저 찾아 재질을 토큰 색으로 다시 입힌다 — 상자·원통 조립은 없을 때만. 실물이면 asset-research.md 절차 → assets.json에 `kind: "model3d"` 후보 → 미리보기(`dk.poster`)를 보여 주고 고르게(A1).
3. 모듈: 도식이면 `route3d.js`를 `custom/<slug>.js`로 복사해 고친다. 실물이면 `data-module="viz/inspect3d.js"` + 설정 JSON(탐색 장: 기획에 `explore: true`, 단계 9까지).
4. `<section data-wait="2600">`(그리기·카메라가 끝난 뒤 찍게) → `deck.mjs capture --steps --only <slug>` 와 `--no3d` 둘 다. 캡처를 열어 아래 자기 점검. 성능은 실제 브라우저에서(`window.__deck3d[slug]` 프레임 중앙값, inspect는 `window.__inspect3d`).
5. 사용자에게 브라우저로 보여 주고 움직임 취향을 묻는다(S2~S3). 답은 decisions.md에 말 그대로.

## 5. 자기 점검 (캡처마다, 하나라도 아니요면 고친다)
1. 헤드라인을 가리고 장면만 봐도 무엇이 무엇보다 긴지/어디에 있는지/무엇으로 이뤄졌는지 3초 안에 보이나?
2. 강조색이 한 군데뿐인가(선택한 경로, 초점 부품의 리더선·숫자)? 흑백으로도 남나?
3. 장면 가장자리가 바탕에 녹아 틀이 안 보이나? 잘린 바닥 모서리·검은 배경이 없나?
4. 라벨이 3D 물체·다른 글·단계 목록과 겹치지 않나? 분해한 부품이 카메라 쪽으로 날아와 화면 밖·글 위로 가지 않나(분해 방향을 카메라와 비껴서, 그 단계 카메라 거리를 늘려서)?
5. 3D 화면과 `--no3d` 화면의 라벨 자리·구도가 같은가?
6. 근거 비율 검사가 통과했나(검수 ERROR 0)? 하단에 "도식/어림 형상/예시 치수"가 있나?
7. 단계 수가 대본의 [→]와 맞나? 들어올 때 갑자기 움직이지 않나?
8. 실제 브라우저에서 45fps 이상인가? 처음 단계 전환 때 멈칫이 없나?

## 6. 인터랙션 (3D 밖)
라이브 앱 iframe 시연(키 넘김·백업 캡처), 오프라인 QR, 출처 팝업, 단축키로 여는 숨김 장, 전체화면 버튼, 카운트업과 "모양은 같고 모션만" 애니메이션은 [3d-interactions.md](3d-interactions.md).
