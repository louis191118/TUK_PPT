# 질문 은행 — 언제, 무엇을 사용자에게 묻나

이 목록은 실제 발표 덱 한 편을 만들면서 사용자가 **중간에 끼어들어 방향을 바꾼 지점**을 모은 것이다. 그때마다 장을 다시 짜거나 다시 그렸다. 같은 지점을 미리 질문으로 만들면 재작업이 줄고 맥락이 처음부터 정의된다.

## 묻는 원칙
1. **구조를 바꾸는 것은 먼저, 취향은 보여 주고 묻는다.** 청중·목적·시간·채점 기준·정본 자료는 `/kpu-ppt init`에서 묻는다. 밀도·미니멀 정도·형태 같은 취향은 말로 물으면 답이 안 나온다. 시안이나 첫 빌드를 **보여 준 다음** 묻는다(실제 의견도 "브라우저로 본 뒤" 나왔다).
2. `AskUserQuestion`으로 묻는다. 한 번에 4개까지, 질문마다 선택지 2~4개, **추천을 첫 선택지**에 "(추천)"으로 둔다. 사용자는 언제나 직접 쓸 수 있다.
3. 이미 `brief.md`나 `decisions.md`에 답이 있으면 묻지 않는다. 사용자가 "알아서 해"라고 하면 아래 기본값을 쓰고 기본값을 썼다고 `decisions.md`에 적는다.
4. 답은 **사용자 말 그대로** 날짜와 함께 `decisions.md`에 쌓고(`- 2026-11-17 [outline] "국내 사례는 조금만" → 사례 장 없이 2장에 한 줄`), 구조화된 값은 `brief.md`의 해당 칸에 쓴다.
5. 질문은 그 단계의 산출물을 승인받을 때 같이 묻는다. 단계 사이에 따로 멈추지 않는다.

## init — 구조를 정하는 질문 (먼저 묻는다)
| # | 질문 | 선택지 (첫째가 기본) | 왜 묻나 (실제로 생긴 일) | 기록 |
|---|---|---|---|---|
| I1 | 누가 듣고, 누가 평가하나요? | 강의 과제(교수·조교) / 공모전·심사위원 / 사내·고객 / 일반 청중 | 같은 덱도 "강사 기준 50점, 공모전 기준 59점"으로 갈렸다. 기준이 달랐기 때문이다 | brief.audience |
| I2 | 과제·심사 기준 원문이 있나요? 붙여 주세요 | 붙여 넣기 / 없음 | 평가: "요구하지 않은 산식 정밀도에 시간의 절반을 쓰고, 과제 본체는 회색 한 줄." 기준을 늦게 봐서 생긴 일 | brief.rubric (원문 그대로) |
| I3 | 발표 시간은? 넘으면 감점인가요? | 정해진 시간(분) + 엄격 / 대략 | 15장 11분 35초로 범위 초과 → 13장으로 압축. 서류상 목표는 제한의 93% (전환·시연 지연분) | brief.time_limit, time_target |
| I4 | 내용의 정본이 되는 자료가 있나요? (기획서·보고서·데이터) | 파일 경로 / 없음, 조사로 시작 | "처음 기획 이거인건 알지?" — 정본을 놓치고 다른 방식으로 계산했다가 다시 만들었다 | brief.canon |
| I5 | 보여 줄 실물이 있나요? (앱·사이트·제품·시연) | 없음 / 있음(URL·경로) | 실물이 있으면 시연 장·백업 캡처·QR 모듈이 필요하다 | brief.demo |
| I6 | 꼭 지킬 이름·용어가 있나요? | 없음 / 있음 | 서비스 이름·용어를 중간에 바꾸면 모든 장을 다시 고친다 | brief.terms |
| I7 | 발표자는 몇 명이고 장을 나눠 맡나요? | 1명 / 여러 명(이름은 나중에) | 노트에 담당·시각을 넣는다 | brief.speakers |
| I8 | 화면 글과 대본의 말투는? | 화면 개조식 명사형 + 대본 하십시오체 / 화면·대본 모두 해요체 / 영어 | 말투는 모든 장에 걸린다 | brief.voice |

## 기본값 (묻지 못했거나 "알아서"일 때)
청중 = 평가자 있는 발표, 시간 목표 = 제한의 93%, 부록 없음, 장 수 제한 없음, 청중 참여 없음, 한계는 평가자가 물을 것만 화면, 밀도 = 그림 하나 + 라벨 + 근거 숫자 2~4줄, 움직임 = 설명할 때만, 말투 = 화면 개조식 명사형 + 대본 하십시오체(한국어).
