# 그림 — 근거 → 그림 (장마다 설계한다)

그림은 메뉴에서 고르지 않는다. **장마다 그 장의 설명 목적에서 출발해 직접 설계한다.** 아래 참고 패턴은 비슷한 문제를 푼 예시일 뿐이고, 그대로 맞을 때만 가져다 쓴다. 좋은 그림은 대개 그 주제에만 있는 단위·비유·배열에서 나온다(예: "1km = 한 칸"으로 거리 차이를 칸 수로, "탑승 63분 + 빗금 14분"으로 계산에서 빼는 구간을).

## 설계 절차 (장마다)
1. **설명 목적을 한 문장으로** 다시 쓴다(outline·spec에 있음).
2. **보여야 할 관계 하나**를 정한다: 무엇이 무엇보다 큰가 / 언제 뒤집히나 / 무엇이 무엇을 낳나 / 어디에 있나 / 무엇이 빠졌나 / 얼마나 쌓이나. 관계가 둘이면 장을 나누거나 단계로 나눈다.
3. **그 관계를 시각 변수로 옮긴다.** 정확히 읽히는 순서: 같은 축 위의 위치 > 길이 > 각도·기울기 > 면적 > 색의 진하기. 비교는 위치·길이로, 강조는 색 하나로, 순서는 왼쪽 → 오른쪽(또는 위 → 아래)으로.
4. **주제의 단위를 찾는다.** 청중이 아는 것 하나로 바꿀 수 있나(칸, 타일, 휘발유 L, 교실 수, 하루 몇 분). 바꿀 수 있으면 그것이 그림의 주인공이다.
5. **단계(최대 3)를 정한다**: 보통 비교 대상 → 우리 값 → 주석. 단계마다 무엇이 나타나고 무엇이 흐려지는지.
6. **두 안을 그려 본다**(중요한 장: 산식·과정·비교·차별점). 각각 캡처해 보고, 아래 "자기 비판"으로 고르거나 사용자에게 보여 준다(질문 B1).
7. 참고 패턴이 그대로 맞으면 패턴을 쓰고, 조금이라도 비틀어야 하면 패턴 코드를 `custom/<slug>.js`로 복사해 고친다.

## 원칙 (자율 설계에서도 지킨다 — `deck check`가 일부를 검사)
- 헤드라인 = 주장, 본문 = 그 주장을 보여 주는 그림 하나, 글은 그림의 라벨로만. 3초 안에 그림만 보고 헤드라인이 맞다고 느껴져야 한다.
- 색은 의미다. 강조색은 우리 값·선택·지금 말하는 것 **하나**에만. 나머지는 회색 단계.
- 막대·면적은 0부터. 이중 축·3D 차트·파이·무지개 색 금지. 범례 대신 직접 라벨.
- 글자는 화면 기준 24px 이상(SVG 안 글자도). 넘침·겹침 없음.
- 상자·카드·테두리로 묶지 않는다. 정렬선·간격·위계로 구분한다(references/design.md).
- 숫자는 `ctx.num(id)`로만. 사실 문장이 근거에서 왔으면 `ctx.num(id)`를 한 번 불러 하단 출처에 붙인다. 이미지는 `ctx.asset(id)`(고른 에셋만).
- 실제가 아닌 것은 표시한다: 도식 지도 "지도 도식", 모의 화면 흑백 + 점선, 예시 값.

## 그리기 도구 (custom/<slug>.js)
```html
<figure class="viz body" data-viz="custom" data-module="custom/<slug>.js">
  <script type="application/json">{ "아무 설정": "그림에 넘길 값" }</script>
</figure>
```
```js
export default function draw(host, { cfg, num, asset, N, fmt, svg, el, text, g }) {
  const s = svg(host, 1632, 640, '그림이 말하는 것 한 문장 (스크린리더)');
  const a = num('route-a');                 // { value, text, unit } · 하단 출처 자동
  s.append(el('rect', { x: 0, y: 40, width: a.value * 20, height: 48, rx: 6, class: 'bar pk s1' }));
  text(s, 0, 24, 'lbl', `경로 A ${a.text}${a.unit}`);
}
```
- 좌표는 실제 px(본문 폭 1632, 높이 670까지). viewBox = 실제 크기라 SVG 글자 px = 화면 px.
- 쓸 수 있는 CSS 클래스: 막대 `bar`·`bar pk`·`bar off`, 선 `ln`·`ln pk`·`axis`·`base`·`grid`·`ref`(점선 기준)·`arrow`·`dash-ln`·`leader`, 점 `dot`·`dot pk`·`dot ink`·`ring`, 글자 `ttl`(30px 700)·`val`(30px 600)·`lbl`(26px)·`note`(26px 흐림)·`big`(96px 강조), 정렬 `mid`·`end`, 강조 글자 `pk`.
- 단계: `s1~s3`(그 단계부터 보임) · `a1~a3`(그 단계 전엔 강조색 대신 회색) · `d1~d3`(그 단계부터 흐리게) · `hx h1~h3`(그 단계에서만 진하게).
- 색·글자 크기를 코드에 쓰지 않는다. 새 시각 규칙이 필요하면 `web/css/custom.css`에 토큰으로.
- HTML 요소가 더 쉬우면(긴 글, 줄바꿈) host에 div를 넣어도 된다. 같은 클래스·토큰을 쓴다.

## 자기 비판 (캡처를 열어 보고, 하나라도 "아니요"면 고친다)
1. 헤드라인을 가리고 그림만 보면 무슨 말인지 아는가?
2. 강조색이 한 군데뿐인가? 흑백으로 바꿔도 강조가 남는가?
3. 이 그림이 아니어도 되는 장식(아이콘, 배경, 상자)이 있는가?
4. 비교하는 것들이 같은 축·같은 기준선에 있는가?
5. 라벨을 읽으려고 눈이 그림 밖 범례로 왔다 갔다 하는가?
6. 단계마다 새로 나타나는 것이 대본의 [→]와 맞는가?
7. 청중 맨 뒷줄에서 가장 작은 글자를 읽을 수 있는가(24px 이상)?

## 참고 패턴 (예시, 제약 아님)
`data-viz="<이름>"`으로 바로 쓸 수 있다. 설정과 모양은 [viz-patterns.md](viz-patterns.md), 실제 렌더는 저장소 `examples/gallery/`.

| 관계 | 패턴 | 이런 때 다른 길을 찾는다 |
|---|---|---|
| 무엇이 더 큰가 | `bars`, `hero` | 차이가 작아 막대로 안 보이면 → 단위를 바꿔(칸·타일) 차이를 세게 |
| 언제 뒤집히나 | `groups` | 반례가 조건 하나면 → 같은 막대에 조건만 바꿔 단계로 |
| 어떻게 변했나 | `line` | 점이 3개 이하면 → 막대나 숫자 두 개로 충분 |
| 무엇이 얼마를 차지하나 | `stack` | 한 조각만 중요하면 → 그 조각만 크게(hero) |
| 얼마나 쌓이나 | `tiles` | 단위가 너무 많으면(1,000+) → 친숙한 환산 하나로 |
| 어떻게 작동하나 | `flow`, `chain`, `cycle` | 실물이 있으면 → 실제 화면 + 리더선(`screen`) |
| 어떻게 계산했나 | `equation` | 항이 4개 넘으면 → 장을 나누거나 항 하나만 펼쳐서 |
| 언제 무엇이 | `timeline` | 사건이 2개면 → 대비(`contrast`) |
| 둘은 함께 움직이나 | `scatter` | 점이 적으면 → 이름 붙인 점 몇 개만 |
| 무엇이 다른가(차별점) | `position`, `matrix`, `contrast` | 축이 억지스러우면 → 대비 한 장 |
| 무엇으로 이뤄졌나 | `tree` | 단계가 깊으면 → 한 가지만 펼침 |
| 무엇이 빠졌나(한계·과제) | `gaps` | — |
| 어떻게 골랐나(기준) | `filter` | — |
| 누가 무엇을 주고받나 | `relations` | 행위자가 6개 넘으면 → 둘씩 나눠 |
| 어디서·어떤 경로로 | (패턴 없음, 직접) · 3D 도식 장면 | 평면 도식 지도 + "지도 도식" 표기, 라벨 4개 이하. 같은 장소 위 두 선택을 입체로 겹쳐야 하면 `3d.md` 도식 장면(build3d → stage3d) |
| 실물이 무엇으로 이뤄졌나 | 3D 에셋 소개(`viz/inspect3d.js`) | 외관·부품 사진 한 장으로 충분하면 → `screen`·사진. 부품 배치·분해가 설명이면 references/3d.md 에셋 소개 |
